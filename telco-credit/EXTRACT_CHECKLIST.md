# چک‌لیست استخراج — همین را بکش

> نسخهٔ عملیاتی. دلیل هر تصمیم در `extraction_spec.md` و `label_spec.md` است.

## خروجی چه شکلی است

**یک جدول. یک سطر به ازای هر (مشترک، کوهورت).**

اگر ۳۰۰ هزار مشترک و ۳ کوهورت بگیری، جدول نهایی ۹۰۰ هزار سطر دارد.

## خط زمان

یک تاریخ در گذشته انتخاب کن (`T0`). مثلاً سه تا، با فاصلهٔ ۳ ماه.

```
   ◄──── ۱۲ ماه قبل ────►  │ T0 │  ◄──── ۶ ماه بعد ────►
         فیچرها                          لیبل
```

هر کوهورت ۱۸ ماه داده می‌خواهد. اگر تاریخچه‌ات ۱۸ ماه است، پنجرهٔ فیچر را ۹ ماه کن
تا دو کوهورت جا شود.

---

# بخش ۱ — پنل ماهانه ⭐ قلب کار

برای **هر یک از ۱۲ ماه قبل از T0**، چهار ستون. جمعاً ۴۸ ستون.

| ستون | یعنی چه |
|---|---|
| `bill_m1 … bill_m12` | مبلغ صورتحساب آن ماه |
| `paid_m1 … paid_m12` | چقدر واقعاً پرداخت شد |
| `due_date_m1 … due_date_m12` | سررسید آن قبض |
| `settle_date_m1 … settle_date_m12` | تاریخی که قبض **کامل** تسویه شد (≥۹۸٪ مبلغ) |

`m1` قدیمی‌ترین، `m12` آخرین ماه قبل از T0.

**چرا ۴۸ ستون و نه میانگین:** از این چهار تا در پایتون حدود ۲۵ فیچر در می‌آید
(میانگین، نوسان، روند، سرعت پرداخت، نسبت پرداخت، ظرفیت اثبات‌شده...). اگر میانگین
بگیری، آنها را برای همیشه از دست داده‌ای. دو مشترک با میانگین یکسان می‌توانند یکی
ثابت باشد و یکی در حال سقوط.

**اگر فرمت بلند راحت‌تر است** (یک سطر به ازای هر مشترک-ماه) هم خوب است. در پایتون
pivot می‌کنیم. فقط تجمیع‌شده نباشد.

---

# بخش ۲ — رویدادها ⭐ سطر جدا، نه تعداد

**قطعی‌ها** — همهٔ رویدادهای ۱۲ ماه قبل از T0:

| ستون | چرا لازم است |
|---|---|
| `suspend_date` | تازگی. قطعی ۱۱ ماه پیش با ماه گذشته فرق دارد |
| `suspend_type` | ⚠️ **دوطرفه در برابر میان‌دوره — حیاتی** |
| `reason` | عدم پرداخت یا چیز دیگر |
| `debt_amount` | شدت |
| `debt_days` | مدت |
| `restore_date` | چند روز طول کشید پول بدهد و وصل شود |

> ⚠️ **قطع میان‌دوره و قطع دوطرفه باید قابل تفکیک باشند.** میان‌دوره وقتی مصرف به سقف
> اعتبار می‌رسد شلیک می‌شود — این مصرف است نه بدحسابی. اگر با هم قاطی شوند،
> پرمصرف‌ترین مشترکینت بد برچسب می‌خورند. اگر کد نوع جدا ندارد، همین الان بگو.

**بدهی‌ها** — همهٔ رویدادهای ۱۲ ماه قبل از T0: `تاریخ`, `مبلغ`, `تعداد روز`

# بخش ۳ — وضعیت در لحظهٔ T0

| ستون | چرا |
|---|---|
| `tenure_months` | ماه‌های حضور در شبکه |
| `credit_ceiling` | سقف اعتبار شماره — قضاوت ریسک خودِ اپراتور |
| `autopay_flag` | پرداخت خودکار فعال است؟ |
| `deposit_amount` | ودیعه |
| `n_services` | موبایل / ثابت / TV |
| `current_debt_amount`, `current_debt_days` | بدهی همین الان |
| `sim_type`, `customer_type`, `status` | دائمی؟ حقیقی؟ فعال؟ |

---

# بخش ۴ — مصرف (اینجا میانگین کافی است)

برای این گروه پنل لازم نیست. **میانگین ۳ ماهه و ۱۲ ماهه** بگیر:

```
data_gb · voice_minutes · sms_count · درآمد دیتا · نسبت درآمد دیتا به کل
تعداد خرید بستهٔ گران · تعداد تماس بین‌الملل · روزهای فعال
```

اینها فیچرهای درجه دو هستند — نشانگر اندازه و تعامل، نه خوش‌حسابی. ارزش دارند ولی
سرنوشت مدل را تعیین نمی‌کنند.

---

# بخش ۵ — دستگاه (اختیاری)

`رده قیمتی از TAC` · `سن دستگاه` · `تعداد تعویض ۱۲ ماه` · `تعداد تعویض سیم‌کارت ۱۲ ماه`

تعویض سیم‌کارت برای مدل ضعیف است ولی برای **تشخیص تقلب** حیاتی.

---

# بخش ۶ — فقط برای تست عدالت، نه برای مدل

`gender` · `age`

استخراج شوند تا بررسی کنیم مدل تبعیض غیرمستقیم ندارد. وارد ورودی مدل **نمی‌شوند**.

---

# بخش ۷ — لیبل ⭐

برای **۴ قبض بعد از T0** (ماه‌های T0 تا T0+3):

```
bill_o1..o4 · due_date_o1..o4 · settle_date_o1..o4 · paid_o1..o4
```

**مهم:** `settle_date` باید تا **T0+6 ماه** رصد شود، نه فقط ۴ ماه. قبض چهارم باید
فرصت داشته باشد به ۶۰ روز تأخیر برسد.

**به‌علاوه:**
- قطع دوطرفهٔ بابت عدم پرداخت در ۶ ماه بعد از T0 → بله/خیر
- پرچم حذف: اختلاف صورتحساب · فوت · تقلب · خطای صدور · ترک شبکه در پنجره

لیبل خودش را در پایتون می‌سازیم:

```
y = 1 اگر:  بیشترین تأخیر ≥ ۶۰ روز
       یا   ۲ قبض یا بیشتر با تأخیر > ۱۵ روز
       یا   قطع دوطرفه
```

---

# بخش ۸ — یک جدول کوچک جداگانه ⭐ فراموش نشود

**شاخص ماهانهٔ شبکه** — یک جدول با ۲۴ سطر:

```
ماه تقویمی  |  میانهٔ قبض کل جامعه در آن ماه
```

به خاطر همان دو فاز افت درآمد. با این جدول همهٔ مبالغ را نسبت به شبکه نرمال می‌کنیم،
تا شوک شبکه‌ای با سقوط فردی اشتباه گرفته نشود. **بدون این، موتور سقف به کسانی که
قبضشان بیشتر افتاده وام بزرگ‌تر می‌دهد** — یعنی دقیقاً برعکس.

ضمناً ماه‌های دقیق آن دو فاز را هم بگو تا علامتشان بزنیم.

---

# سه تله‌ای که همه در آنها می‌افتند

**۱. همه چیز نسبت به `T0`، نه نسبت به امروز.**
هر فیلتر یا پنجره‌ای که از امروز حساب شود، وارد پنجرهٔ لیبل می‌شود و مدل را نابود
می‌کند. امتیاز خوش‌حسابی، دروازهٔ قطعی، فیلتر یک‌ساله — همه نسبت به `T0`.

**۲. تأخیر از سررسید حساب می‌شود، نه از تاریخ صدور.**
اگر از صدور حساب کنی، نیمی از جامعهٔ پس‌پرداخت هر ماه «دیر» می‌شوند و نرخ بد بی‌معنا
بالا می‌رود.

**۳. دو نوع قطعی با هم قاطی نشوند.** (بخش ۲)

# حجم

**۳۰۰ هزار تا ۱ میلیون مشترک** به‌صورت نمونهٔ تصادفی، ضربدر ۳ کوهورت.

روی ۱۰ میلیون اجرا نکن — برای آموزش لازم نیست و هر چرخهٔ آزمایش را ساعت‌ها طول می‌دهد.
کل جامعه فقط در آخر، برای امتیازدهی نهایی.
