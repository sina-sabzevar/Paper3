# Telco micro-credit scoring — مدل اعتبارسنجی و تخصیص خط اعتباری

مدل تصمیم‌گیری برای دادن اعتبار خرد به مشترکین **سیم‌کارت دائمی**، قابل بازپرداخت در
**۴ قسط** روی صورتحساب ماهانه.

## فایل‌ها

| مسیر | توضیح |
|---|---|
| `telco_credit_scoring.ipynb` | نوت‌بوک یکپارچه، از استخراج داده تا نتیجهٔ نهایی و MCDM |
| `data/subscribers.csv` | **داده واقعی را اینجا بگذارید.** اگر نباشد، نوت‌بوک دادهٔ مصنوعی می‌سازد و کامل اجرا می‌شود |
| `outputs/` | خروجی‌های اجرا: نمودارها، جدول امتیاز، جدول رتبه‌ها، سناریوهای MCDM، فایل تصمیم |

## اجرا

```bash
pip install numpy pandas matplotlib scikit-learn scipy jupyter tabulate
jupyter lab telco_credit_scoring.ipynb      # یا: Run All
```

بدون `data/subscribers.csv` هم سر تا ته اجرا می‌شود (دادهٔ مصنوعی ۶۰ هزار مشترک).

## ساختار تصمیم

```
دیتابیس
   │
   ├─ دروازه‌های سیاستی ──────────► چه کسی حتی وارد ارزیابی نمی‌شود
   │
   ├─ اسکورکارت (لجستیک روی WOE) ─► PD: احتمال نکول
   │      └─ کالیبراسیون + ضریب شوک پرداخت
   │
   ├─ رتبه‌بندی A..G ─────────────► سیاست هر رتبه (α، ضریب مصرف، سقف مطلق)
   │
   ├─ موتور سقف ──────────────────► L = min(توان پرداخت، نسبت مصرف، وثیقه، سقف رتبه)
   │
   ├─ زیان مورد انتظار ───────────► EL = PD × LGD × EAD، سود خالص هر وام
   │
   └─ MCDM ───────────────────────► انتخاب سناریوی نهایی بین اهداف متضاد
```

## دو پارامتری که باید از دادهٔ خودتان برازش شود، نه حدس

1. **`lgd` و `ead_factor`** — از منحنی وصول تاریخی بدهی‌های معوق. دادهٔ آن موجود است.
2. **`shock_uplift_k`** — حساسیت PD به شوک صورتحساب؛ بعد از ۶ ماه وام واقعی قابل برازش است.

تا آن موقع مقادیر پیش‌فرض محافظه‌کارانه‌اند و در `CONFIG` مستند شده‌اند.

## نکتهٔ کلیدی روی تارگت

برچسب نکول واقعی وجود ندارد (هنوز وامی داده نشده). تارگت یک **جانشین رفتاری** است:
بدحسابی قابل مشاهده در صورتحساب، در پنجرهٔ نتیجهٔ ۴ ماهه. این تارگت PD را
**خوش‌بینانه** برآورد می‌کند و جبرانش در نوت‌بوک آمده (ضریب شوک + سلول کنترل تصادفی).
